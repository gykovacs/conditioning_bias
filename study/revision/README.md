# Revision scripts (paper_v2.tex validation and regeneration)

These scripts produced the evidence and the tables/figures behind `paper_v2.tex` (the revised
paper in `paper_2023_conditioning_bias_springer/`) and the write-up in `reviews/findings.md` and
`reviews/revision_plan.md`. They assume the same environment as the rest of `study/` (same conda
env, `study/data/` populated per the top-level `README.md`) and mostly `sys.path`-insert the repo
root and `study/`, then `os.chdir('study')`, to reuse `config.py`, `datasets.py`, `evaluation.py`
and the `conditioning_bias` package. Paths are currently hardcoded to this repo's absolute path.

**Not wired into a single entry point** — these were written and run interactively over the
course of the revision, not designed as a clean pipeline. The list below gives the order they were
actually run in and what each one depends on, so the whole chain is reconstructable if needed.

## Current / authoritative (feed the current paper_v2.tex tables and figures)

1. **`new_datasets_setup.py`** — model selection + baseline K=5/400-repeat evaluation for the two
   replacement regression datasets (`concrete`, `boom_bikes`), mirroring `study/001-model-selection-*`
   and `study/005-evaluation.ipynb` exactly. Writes into `study/data/params_{dtr,rfr}.csv` (appends,
   replacing the `o-ring`/`diabetes` rows) and `study/data/evaluation_{dtr,rfr}_newds.csv`.
2. **`newds_asymmetry_check.py`** — confirms `concrete`/`boom_bikes` don't reproduce the
   `o-ring`-style hyperparameter-selection instability (they don't: score differences ~0.0002-0.006pp
   vs. `o-ring`'s 22pp).
3. **`real_data_ksweep_v2.py`** — the main event. Full K-sweep (K ∈ {5,10,15,20}, capped per-dataset
   for small-sample stability) across all 40 datasets × 4 estimators, computing: absolute
   per-operator mean scores, `<=_vs_<`, `avg_vs_worst`, `select_vs_avg`, `select_vs_worst`, and
   `select_hit_rate` (the in-sample operator-selection proxy comparisons). Was run twice: the first
   pass wrote `ksweep_results_v2.csv` with a bug in `select_hit_rate` (tie-breaking convention
   shared between the selection and evaluation sides spuriously inflated it); the bug was fixed
   in-place in this same script (see the docstring in `make_rows`) and it was re-run to produce
   `ksweep_results_v3.csv` — confirmed byte-identical to v2 on every other column (fully
   deterministic re-run, same seed). **`ksweep_results_v3.csv` is the current source of truth.**
   Each full run takes roughly 11 hours on the machine this was developed on (RF fits dominate).
4. **`gen_tree_figures.py`** — regenerates `forest_v2.pdf`, `forest3_v2.pdf`, and the corrected
   `forest2_v2.pdf` (the original hand-made mirrored-tree figure had two threshold labels swapped;
   this version is verified against the mirroring definition by hand, see `reviews/findings.md`).
5. **`gen_tables.py`** — generates every `tab_*_v2.tex` file consumed by `paper_v2.tex`
   (`tab_datasets_regression_v2`, `tab_presence_{classification,regression}_v2`,
   `tab_results_{classification,regression}_v2`, `tab_meta_v2`, `tab_meta_select_v2`,
   `tab_hitrate_v2`) from `ksweep_results_v3.csv`, `splits_*.csv`, and `params_*.csv`.
   `tab_datasets_classification_v2.tex` is not generated by this script — the classification pool
   is unchanged from the original study, so it's a direct copy of `tab_datasets_classification.tex`.
6. **`gen_heavytail_fig.py`** — generates `heavytail_v2.pdf` (the rank-ordered effect-size figure)
   from `ksweep_results_v3.csv`.

## Diagnostic / exploratory (informed decisions, not directly regenerating current paper content)

- **`sig_reanalysis.py`** — the first script of the whole revision: re-analyzes the *original*
  `study/data/evaluation_*.csv` (no new experiments) with four significance-testing methods (naive
  pooled Wilcoxon, repeat-mean Wilcoxon, corrected resampled t-test, unpaired). This is the source
  of the headline 131/240 → 3/240 finding that motivated everything downstream.
- **`repeats_vs_k.py`** — demonstrates, on the original data, why more CV repeats can't buy
  significance-testing power past a point (the correction floor `var_d/(k-1)`), and why larger K
  can.
- **`pilot_larger_k.py`** — real re-fits (not formula extrapolation) at K ∈ {5,10,20,30} on 5
  borderline datasets, confirming larger K recovers genuine signal selectively (2 of 5 cases), not
  indiscriminately.
- **`model_selection_lt.py`** — the hyperparameter-selection-asymmetry diagnostic: re-runs model
  selection scored against `<` instead of `<=`, across the *original* 40-dataset pool, comparing
  selected hyperparameters and achieved scores. This is what found the `o-ring`/`diabetes`
  instability that led to their replacement.
- **`synthetic.py`** / **`synthetic_significance_demo.py`** — the synthetic data generator and the
  i.i.d.-replicate significance experiment behind paper_v2.tex §4.9 (Synthetic validation).

## Superseded (kept for provenance, not part of the current reproducible path)

- **`real_data_ksweep.py`** — the first version of the K-sweep (K ∈ {10,15,20} only, reusing K=5
  from the original study data via `reuse_k5.py`; only computed `<=_vs_<` and `avg_vs_worst`, no
  absolute scores or operator-selection). Fully superseded by `real_data_ksweep_v2.py`.
- **`reuse_k5.py`** — extracted K=5 results from the original study's evaluation CSVs to pair with
  `real_data_ksweep.py`'s output. Not needed once `real_data_ksweep_v2.py` recomputes K=5 fresh.
- **`meta_analysis.py`** — standalone sign-test/Fisher-p meta-analysis script over the old
  `ksweep_results.csv` + `ksweep_results_k5_reused.csv`. Superseded by the meta-analysis logic now
  built directly into `gen_tables.py`, which reads `ksweep_results_v3.csv`.

## Key output files (in `study/data/`, not tracked in git per the top-level README)

`ksweep_results_v3.csv` (current source of truth), `ksweep_results_v2.csv` (superseded, buggy
hit-rate), `splits_{dtc,rfc,dtr,rfr}.csv` (ρ/ρ_k, updated for the `concrete`/`boom_bikes` swap),
`params_{dtc,rfc,dtr,rfr}.csv` (selected hyperparameters, likewise updated).
